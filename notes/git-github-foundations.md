# Git and GitHub Foundations

This is my first practical tool note. It records the concepts behind the change I am making, not a claim that I have mastered Git.

## Core ideas

- **Repository:** A project space that contains files and their change history.
- **README:** The front door of a repository. It explains the purpose, scope, use, and limits of the work.
- **Markdown:** A lightweight writing format for headings, lists, links, and code notes. It keeps technical explanations readable in GitHub.
- **Commit:** A named snapshot of a meaningful change. A good commit says what changed and gives the history a useful checkpoint.
- **Version control:** A way to see how work changed, understand why, and recover from a mistake. It makes learning and research more inspectable.

## GitHub in my four-year system

GitHub is the public evidence layer. It will hold selected code, documentation, permitted data descriptions, project reports, and research notes. The point is to show real development over time: what I tried, what I learned, what I checked, and what remains uncertain.

Notion holds the private strategy and route. GitHub holds the public artifacts that can be inspected.
